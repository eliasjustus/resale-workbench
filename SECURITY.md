# Security in Resale Workbench

Report vulnerabilities through [GitHub private vulnerability reporting](https://github.com/eliasjustus/resale-workbench/security/advisories/new). Include the affected version, impact and a minimal synthetic reproduction. Do not post vulnerabilities, credentials or personal evidence in public issues. If the reporting form is unavailable, open an issue requesting a private reporting channel without disclosing the vulnerability.

Security fixes target the latest release. Response times are best effort; no service-level commitment is provided.

Run the tool locally with evidence you are entitled to retain and process. Listing text, images and model outputs are untrusted input. The manual agent workflow does not provide an operating-system sandbox. Original captures and local audit records can contain sensitive data: keep them private and inspect derivatives before sending them to external services. See [PRIVACY.md](PRIVACY.md).

For ordinary bugs, use synthetic fixtures or a reviewed `resale support-summary` output. Never attach a whole workspace, database, browser profile or real marketplace capture.
